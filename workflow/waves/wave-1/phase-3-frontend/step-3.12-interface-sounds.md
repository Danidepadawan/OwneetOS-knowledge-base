# 3.12 Interface sounds

Up: [[phase-3-frontend]] · Status: **done**

- **Deliverables:** sounds for navigation and feedback, as listed in [[interface-sounds-spec]], played
  from **placeholders** (`frontend/sounds/`, Kenney CC0, generated by
  `tools/sounds/make-placeholders`) until the owner's final sounds arrive (7.7; six of ten
  delivered on 2026-10-09), converted to WAV 48 kHz mono with the silent tail trimmed when the
  package is built (the delivered files stay as made); a sound service in the theme
  (Qt `SoundEffect`, preloaded, no delay), played by the shared navigation components (3.5) so every
  screen gets them; Settings → Sound: "Interface sounds" on/off and volume; silent while a game is
  on screen. Priority-2 sounds are wired when their features arrive (notifications, controllers,
  game launch, on-screen keyboard).
- **Open point from demo 3.6 (2026-10-09):** in the browser some sounds started late or sounded
  different. Likely cause, besides the browser's own latency: PipeWire suspends an idle audio
  output after a few seconds, and waking it delays or cuts the start of the next short sound. The
  interface keeps its audio output awake while it is on screen (e.g. one open stream, or no
  suspend for it); checked on real hardware with the ISO (sounds on time and identical).
- **Outcome (2026-10-11):** `foundation/UiSounds.qml` loads the eleven sounds at start and plays
  what `Nav.feedback` reports (every screen and window: moves, edges, clicks, sections, windows,
  notifications, errors, game launch, on-screen keyboard), at the volume of Settings → Sound
  (perceived scale), not when "Interface sounds" is off nor while a game is on screen; `startup`
  once per boot (`SystemInfo.firstStartThisBoot`); `game-launch` also when Guide brings the home
  screen over a game. The package converts the files (48 kHz mono, silence trimmed: e.g.
  `nav-confirm` 466 → 105 ms) and installs them with Kenney's licence and `SOURCES.md`. Open point
  above: sound outputs no longer sleep (`owneet-hardware` 0.0.4, WirePlumber
  `session.suspend-timeout-seconds = 0`). Checked in the test VM with its virtual sound cards:
  eleven 48 kHz mono streams loaded, both outputs with suspension off, the output recorded while
  the virtual pad pressed buttons peaks at −17.6 dB (−91 dB without presses). To check on real
  hardware: timing (no late or cut clicks) and loudness. owneet-frontend 0.13.0.
- **Hardware test (2026-10-11, NiPoGi on an LG TV):** every sound on time, the on-screen keyboard
  works; but the start-up sound never played, and once the first section change after pairing the
  controller was silent. Cause: the output (HDMI to the TV) was still idle when the first sound
  came, and the TV takes a moment to pick up the audio. Fixed: the interface loops one second of
  silence from its start (the output is running and the TV in sync before the first real sound),
  and the start-up sound waits until that has run for a moment and the sound is loaded. Checked
  in the test VM: one stream always running, the start-up sound recorded at −17.7 dB after the
  interface restarted. owneet-frontend 0.13.1.
